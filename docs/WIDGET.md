# 今日待办桌面小组件

## 添加与操作

安装升级包并打开 App 一次，随后长按 Android 桌面空白处 → 小组件（或窗口小工具）→ 今日有序 → 今日待办。默认约 4×2，可长按调整宽高；不同桌面应用的格子尺寸会有差异。

显示今天未完成任务，按具体时间、同组手动顺序排列。无时间的随后，过期、未来、未安排和已完成任务不列出。按可用空间显示 1–4 条，只显示任务标题与行标记。

- 点任务：打开 App 编辑该任务，完成操作也在 App 中进行。
- 点＋：打开“新建待办”，默认安排今天；不会提前创建空任务。
- 点卡片空白处：打开今天页。任务已删除时会提示，不创建替代任务。
- 正在编辑或弹窗中再次点击小组件时，先提示保存／关闭，保护当前输入。
- 没有今日未完成任务时仅保留＋，不填充示例。

1.2.5 起移除标题、日期、数量、时刻、说明与页脚，只保留待办行和右下角＋；行前圆圈是标记，点行在 App 内编辑／完成。外观随 App 的浅／深色设置变化。收工整理提醒单独在更多 → 提醒策略设置，默认每天 21:00，有待整理任务才发送。

## 实现与数据

使用原生 AppWidgetProvider、RemoteViews 和固定行布局，不运行第二份 WebView。实现依据 [Android 小组件说明](https://developer.android.com/develop/ui/views/appwidgets) 与 [可调整布局说明](https://developer.android.com/develop/ui/views/appwidgets/layouts)。

主数据仍在 IndexedDB。业务保存成功后，TodayWidget 桥接把必要的 ID、标题、日期、时间、状态和顺序镜像到 App 私有 SharedPreferences，不复制备注、笔记正文、图片或同步凭证。队列与递增修订阻止旧镜像覆盖新数据；失败在 App 提示并允许重试。

任务保存、完成、删除、改期、备份恢复和主题变化后更新全部实例。原生按本地日期计算内容；有小组件时安排非精确午夜刷新，另有系统周期更新及时间、时区、重启、升级和大小变化后的刷新。无组件时取消午夜更新。系统可能延迟后台刷新，不承诺午夜零延迟或强行停止后刷新。

PendingIntent 显式指向本应用，采用不可变标志和按 action／task ID 区分的 URI。冷启动先等本地数据加载，再消费一次启动请求；已运行应用通过原生事件接入。小组件不直接写业务任务。

## 验证范围

前端契约测试覆盖午夜、无日期排除、必要字段、主题、单调修订、失败重试和浏览器不调用原生。JVM 测试覆盖今日筛选、完成排除、时间／手动排序、换日、时区与大小；Android 资源编译、Release、原生单元测试和 lintVital 通过。

尚无连接手机：桌面选取器展示、大小调整、添加多个实例、冷／热启动点击、中文字体放大、手机横竖屏、真实系统午夜刷新和厂商后台限制仍需实机验收。浏览器截图只表示 App 布局，不作为小组件桌面截图。
